# Лабораторная работа: бронирование жилья

Простое консольное приложение на Python. Четыре файла приложения. Используются обычные классы, словарь, циклы и условия.
Дополнительных библиотек нет. Требуется Python 3.10 или новее.

## Запуск

Распакуйте архив, откройте терминал в папке `booking_simple` и выполните:

```bash
python main.py
```

В Windows можно использовать `py -3 main.py`, в Linux/macOS — `python3 main.py`.
Выбирайте действие по номеру. Для выхода введите `0`.
**Данные хранятся в памяти и исчезают после выхода.**

## Что умеет программа

- Добавлять гостей и жильё, показывать списки.
- Бронировать жильё и рассчитывать стоимость по количеству ночей.
- Проверять даты, количество гостей и занятость жилья.
- Отменять бронь, освобождая даты.
- Удалять жильё, если у него нет истории бронирований.

Цены вводятся в целых рублях, даты — в формате `ДД-ММ-ГГГГ`.
Заезд не может быть в прошлом, выезд должен быть позже заезда.
Заезд в день выезда предыдущего гостя разрешён. Отменённая бронь остаётся
в списке, но не занимает жильё. Для простоты отмена доступна в любое время:
платежей и штрафов в этой лабораторной нет.

## Пример работы

1. Пункт `1`: добавьте гостя Иван. Его номер будет `1`.
2. Пункт `3`: добавьте «Квартира», 3 места, цена 2000. Номер жилья будет `1`.
3. Пункт `5`: гость `1`, жильё `1`, любые будущие даты на 3 ночи, 2 гостя.
   Например, с `10-05-2030` по `13-05-2030`, если эти даты ещё не наступили.
4. Программа покажет стоимость **6000 рублей**.
5. Повторная бронь на эти даты вызовет ошибку.
6. Пункт `7`: отмените бронь №`1`. Теперь эти даты снова свободны.

## Как устроен код

| Файл | Слой | Назначение |
|---|---|---|
| `main.py` | Точка входа | Меню, ввод и вывод |
| `models.py` | dataLayer | Классы Guest, Housing, Booking |
| `repository.py` | repositoryLayer | Добавление, получение, изменение, удаление объектов |
| `service.py` | serviceLayer | Проверки брони, стоимость, отмена |

Путь вызова: меню → сервис → репозиторий.

Создаются три экземпляра одного класса Repository: отдельно для гостей, жилья
и бронирований. У каждого свой словарь и счётчик номеров.
Сервис получает эти репозитории через конструктор и не обращается к словарям напрямую.
Для другого хранилища можно написать класс с теми же методами `add`, `get`,
`get_all`, `update`, `delete` и передать его сервису вместо текущего.
Метод `add` должен назначать номер и возвращать добавленный объект.

Здесь соблюдается разделение ответственности (SRP): меню не рассчитывает цены,
сервис не хранит словари, репозиторий не проверяет занятость жилья.
Передача репозиториев через конструктор позволяет менять хранилище без
переписывания правил бронирования. Абстрактные классы для небольшой работы не нужны.

Главная проверка пересечения двух периодов:

```python
start < booking.end and booking.start < end
```

Если оба условия истинны, периоды пересекаются. Равенство границ допустимо:
в день выезда одного гостя может заехать следующий.

Сервис ожидает числа и объекты date; преобразование строк выполняет меню.
Приложение учебное, для одного пользователя, без БД, авторизации и оплаты.

## Как отправить на GitHub

1. Установите Git и войдите на https://github.com/.
2. Создайте через **New repository** пустой репозиторий `booking-lab`.
   Не добавляйте README и .gitignore на сайте: они уже есть в проекте.
3. Откройте терминал в папке `booking_simple` и выполните:

```bash
git init
git config user.name "Ваше имя"
git config user.email "Ваш email"
git add .
git commit -m "Add booking lab"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/booking-lab.git
git push -u origin main
```

Замените `YOUR_USERNAME` своим логином GitHub. При запросе входа пройдите
авторизацию в браузере. Если Git просит пароль для HTTPS, используйте personal
access token вместо пароля аккаунта. Токен в файлы проекта добавлять не нужно.

После изменений: `git add .`, затем `git commit -m "Update lab"`, затем `git push`.
